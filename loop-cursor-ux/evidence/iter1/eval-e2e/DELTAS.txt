tmux is a terminal multiplexer: a small program that sits between you and one or more shells so those sessions outlive a dropped SSH connection, a closed laptop lid, or a crashed GUI terminal. You attach to a tmux server, which owns sessions. Each session holds windows (like tabs), and each window can be split into panes. Detaching does not stop work. Reattaching from another machine, days later, restores the same layout, running processes, and scrollback.

That persistence is why people still reach for tmux on remote servers. A long compile, a training job, or a database migration can keep running after the network dies. On a laptop it is equally useful: you can leave a development stack—editor, logs, tests—arranged once and return to it without rebuilding the layout. Pairing and teaching also benefit: two people can attach to the same session and see the same terminals, with optional read-only attaches for observers.

tmux is not an editor, an IDE, or a window manager for the whole desktop. It is a durable, scriptable layer for interactive shells. Used that way, it removes a whole class of “I lost my SSH session and my work” accidents, and it turns a blank terminal into a workspace you can leave and return to. Six hundred words is enough to say the rest is practice: attach, split, detach, attach again, until it feels like the terminal you always meant to have.
