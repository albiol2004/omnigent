1. **CONFIRMED — pending user bubble renders below the streaming preview.** `web/src/pages/ChatPage.tsx:861` `mergePendingBubbles`; the insert position at `:516-525` lifts the pending bubble above trailing *elicitation* bubbles and *create-routing chips* only — a trailing live assistant preview bubble is not in that list. For cursor pane-diff streaming the live block frequently is not last.
3. **CONFIRMED — `response_end` deletes an unreplaced live preview.** `web/src/store/chatStore.ts:4847-4853` filters out every `isLiveProvisionalBlock` on stream end. Its comment assumes a committed `text_done` already replaced the preview; when the mirror produces no authoritative item that assumption is false and the only on-screen copy of the text is wiped.
4. **CONFIRMED (mechanism) — `finalizedLiveMessageIds` is a permanent per-connection blacklist on a possibly-stable id.** Set at `web/src/store/chatStore.ts:4577-4589`, gate at `:4349` (`if (finalizedLiveMessageIds.has(messageId)) continue;`), populated at `:4718`, `:4806` and in bulk at `:4847`, cleared only in the `finally` at `:4901`. If that user row never posts, the id is identical across turns and once finalized every later turn's deltas are dropped for the life of the SSE connection. ## Model picker diagnosis (file:line verified, live pane captured read-only)
Path: web → server session-change `type='model_change'` → `_handle_cursor_native_model_change` (`omnigent/runner/app.py:4436-4466`, expected display name from the cache at `:4449`, populated by `GET /v1/sessions/{id}/cursor-model-options` at `:8511-8538`) → `inject_model_command` (`omnigent/cursor_native_bridge.py:790-889`, types `/model <id>` at `:847`, polls `capture-pane` for `Models matching` / `No matches` at `:855-861` with a 5 s budget and a fixed 1.5 s settle).
8. **CONFIRMED — `→` glyph collision.** `cursor-agent` uses `→` as its COMPOSER PROMPT glyph; the live pane renders `  → Add a follow-up` above the model list. `_picker_highlighted_row` (`omnigent/cursor_native_bridge.py:898-904`) returns the FIRST top-down `→` line, i.e. the composer line, never a model row, so `_picker_row_matches_display` (`:907-911`) always fails and the runner 503s with "did not resolve to its exact picker row". Harness-wide, not grok-specific — no model can be switched. `omnigent/claude_native_bridge.py:144-157` and `:3750-3772` already implement exactly this discrimination; cursor's port dropped it. The unit fixture hides it: `tests/test_cursor_native_bridge.py:174` `_IDLE` has no `→` (used at `:204`, `:294`).
9. **CONFIRMED (latent, would bite after 8) — the matcher accepts any variant by prefix.** `:907-911` allows `normalized_row.startswith(f"{display} ")`, so "Cursor Grok 4.6 Low" / "… Fast" / "… Extra High" all match; the picker filtered by `cursor-grok-4.6` shows 7 rows and whichever is highlighted first gets Enter, so a "successful" switch can silently land on the wrong effort variant.
10. **CONFIRMED — the offered option list invents and drops ids.** `omnigent/cursor_native.py:214-292`: `_CURSOR_UNMAPPED_CLAUDE_RE` (`:218`) drops real ids such as `claude-4-sonnet`, while the dotted rewrite synthesises ids that never appear in `cursor-agent models` (e.g. `claude-4.6-sonnet-medium` → `claude-sonnet-4-6`); since the id is typed into the picker filter, an invented id yields a genuine "No matches".
Ground truth on this machine: `cursor-agent models` prints 208 lines including `cursor-grok-4.6-low/-medium/-high/-xhigh` (± `-fast`); `cursor-grok-4.6-high` displays as "Cursor Grok 4.6". The live pane is ~41 columns and WRAPS long rows, and `capture-pane` without `-S` sees only the viewport, so any matcher must tolerate wrapping/truncation and a scrolled list.
`cursor-agent --help` offers `--model <model>` (with bracket overrides e.g. `'claude-opus-4-8[effort=high,fast=false]'`), `--list-models`, `--resume [chatId]`, `--continue`.
