## Problem (diagnosed 2026-09-16)
Trio Omnigent loops create Lead/Evaluator sessions with `sys_session_create(agent_id=...)` (registered agents; provider cursor today, claude-native and codex-native are equally supported roles). Each runs the vendor TUI in a dedicated tmux (`/tmp/omnigent-terminal-*/tmux.sock`, 200-600 MB resident). Ten idle ones from finished loops held ~5 GB and OOM-killed the workspace's Docker daemon. Upstream has the same bug open: omnigent-ai/omnigent#7498 (filed 2026-09-16, unfixed through v0.14.0).

Diagnosed causes, all in this repo:
1. `omnigent/runner/tool_dispatch.py` `_session_close_via_rest` (~5582-5668): after `_close_tree_scope_error` (~5525-5579, the real security boundary: same `root_conversation_id` and non-null `parent_session_id`) passes, a second guard requires `_parse_session_title(title)` (~4089-4113) to yield `<agent>:<title>`; `sys_session_create` children keep their verbatim title, so close returns `session_not_a_sub_agent` before any stop or tombstone. The in-process path in `omnigent/tools/builtins/spawn.py` (~1326, ~1693) has the same shape.
2. Same function ~5636-5646: `event_type` is `stop_session` only when the wrapper label is `CLAUDE_NATIVE_WRAPPER_VALUE`; every other native harness gets `interrupt`, which for Cursor is a soft Escape (`cursor_native_bridge.inject_interrupt`) and for Codex routes through the app-server client (`omnigent/runner/native/interrupt.py` `_codex_interrupt` ~481). Neither kills the tmux pane. `_UNIFORM_STOP` (~207) already has a Cursor entry whose `_uniform_stop` (~381-413) calls `cursor_native_bridge.kill_session` + `_teardown_session_terminals`; Codex has no stop path at all (`stop()` ~291 routes codex/pi to interrupt), and `omnigent/codex_native_bridge.py` has no `kill_session`.
3. Fork commit 760441438 (kill-on-close) added a leftover-pane SIGKILL escalation (`_recorded_tmux_pid`, `_tmux_pane_pid`, `_kill_leftover_tmux_process`) only to `omnigent/claude_native_bridge.py` (~3310-3390); `cursor_native_bridge.kill_session` (~934-944) and the other native bridges are plain `tmux kill-session`.
4. Idle pane reaper (`omnigent/terminals/pane_reaper.py`, wired in `omnigent/runner/app.py` ~10617-10686, 1h default) reaped some Cursor panes but missed most leaked ones for 15+ hours; the runner log shows `process_manager._idle_reaper_loop` ("reaping idle harness subprocess", `omnigent/runtime/harnesses/process_manager.py` ~1420-1455, `release` ~1040) firing ~1h after idle for those conversations, after which the pane reaper never reaped them. Hypothesis to confirm with a test: the harness-subprocess release drops state the pane reaper's busy check or `native_panes()` listing depends on (or the busy check keeps returning true), orphaning the pane. Evidence: /home/coder/.omnigent/logs/runner/runner-13839e479047419e8d446c50a2cca38f-20260915-140650-755225.log (read-only), conversations 6b7c939e..., 55913c8a..., cbd5aeac..., 1c0a0a25..., 393b95d8... never pane-reaped; 492e2359... and b3dbfcd8... were.

## Acceptance
- Close accepts children the caller created: in `_session_close_via_rest` and the in-process close, a target that passes the tree-scope check (same root, `parent_session_id` set) must be closable even when its title does not parse; derive the tombstone label from the snapshot's agent fields (see how ~3007-3013 already does this for display) and keep rejecting true top-level sessions (`parent_session_id` None) with `session_not_a_sub_agent`. Registration-anchor sessions created via `config_path` with no parent must remain non-closable.
- Close tears down the harness for Claude, Codex and Cursor uniformly: route `stop_session` for `CLAUDE_NATIVE_WRAPPER_VALUE`, `CODEX_NATIVE_WRAPPER_VALUE` and `CURSOR_NATIVE_WRAPPER_VALUE` (and, if cheap, every wrapper with a `_UNIFORM_STOP` entry); add a real Codex stop in `NativeInterruptRunner.stop` that kills the Codex tmux pane (add `kill_session` to `codex_native_bridge` mirroring Cursor's), runs `_teardown_session_terminals`, and calls `teardown_codex_native_app_server` (`omnigent/runner/native/orchestration.py` ~199) so no app-server or forwarder survives. A failed stop must still tombstone (existing behaviour).
- Leftover-process escalation shared: factor the SIGKILL fallback from `claude_native_bridge` into one helper reused by the Claude, Codex and Cursor `kill_session` implementations (other bridges may adopt it if trivial).
- Reaper orphaning: write a regression test that reproduces the interaction between `process_manager.release` and the native pane reaper for a cursor/codex/claude conversation; if the hypothesis holds, fix it so an idle pane is still reaped after the harness subprocess is released (or is released together with it). If the hypothesis is disproved, record the actual cause with evidence in REPORT.md and fix that instead; do not leave the leak unexplained.
- Tests extended in the files that already cover these paths: `tests/runner/test_runner_dispatch.py` (close cases ~5850-6061), `tests/tools/builtins/test_sys_session.py` (~776-823), `tests/runner/test_native_interrupt_runner.py` (~285-333 stop/teardown), `tests/test_claude_native_bridge.py` (~3892-4000 kill escalation), `tests/test_cursor_native_bridge.py`, `tests/test_codex_native_bridge.py`, `tests/terminals/test_pane_reaper.py`.
