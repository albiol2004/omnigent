# Scout Report: Codex native tmux kill surface

## Headline finding

**Codex-native has no tmux surface at all.** `grep -i tmux` on `omnigent/codex_native_bridge.py` returns *no matches*. There is no `kill_session`, no `tmux.json`, no `_TMUX_FILE`, no `write_tmux_target`, no `bridge_dir_for_session_id` (Codex uses `bridge_dir_for_bridge_id` instead). So there is **nothing to mirror** from Cursor's `kill_session` — the Codex "hard stop" is a different mechanism (tear down the app-server subprocess, not `tmux kill-session`).

## Answer to the Lead's question

**Codex does NOT use a tmux advertisement.** There is no `tmux.json` in the Codex bridge dir and no `kill_session` function to copy. The Codex hard-stop surface is `teardown_codex_native_app_server(session_id)` (`omnigent/runner/native/orchestration.py:199-225`), which closes the app-server subprocess from `_AUTO_CODEX_APP_SERVERS` and cancels its forwarder. It is keyed by `session_id`, not `bridge_dir`.

### Recommended shape for `NativeInterruptRunner.stop` Codex branch

Mirror `_claude_stop` (`interrupt.py:438-479`) but swap the tmux kill for the app-server teardown:

1. Add `teardown_codex_native_app_server` to the existing `from omnigent.runner.native.orchestration import (...)` block at `interrupt.py:43-47`.
2. In `stop()` (305-308), branch `codex` to a new `_codex_stop` instead of falling through to `interrupt`. Keep `pi` on the interrupt path unless it gets its own teardown later.
3. `_codex_stop(conv_id)` should:
   - `await teardown_codex_native_app_server(conv_id)` — this already calls `_cancel_auto_forwarder_task` internally, so do **not** call `_cancel_auto_forwarder_task` again separately (unlike `_claude_stop` which calls it at 463 because Claude's `kill_session` does not).
   - `await self._teardown_session_terminals(conv_id)` (328-353) — close registered terminals + publish `terminal_deleted`.
   - `self._publish_event(conv_id, {"type": "session.status", "status": "idle"})`.
   - `self._mark_subagent_terminal_and_wake(conv_id, status="cancelled", output="[System: sub-agent stopped]")` + the same delivery-ack warning block as 470-477.
   - Return `Response(status_code=204)`.

No `bridge_dir` resolution is needed for the kill step (the app-server is keyed by `conv_id`). If a `state.json` cleanup is also desired, `clear_bridge_state(bridge_dir)` exists at `codex_native_bridge.py:629` and could be called after resolving `bridge_dir` via `bridge_dir_for_bridge_id(labels[CODEX_NATIVE_BRIDGE_ID_LABEL_KEY])` using the same `_session_labels_for_runner_spawn` pattern as `_codex_interrupt` (494-499) — but that is optional cleanup, not required for parity with the tmux kill.
